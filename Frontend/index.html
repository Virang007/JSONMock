Guide

Examples use the Fetch API, but any HTTP client works. 

fetch('http://localhost:3000/posts/1')
  .then(response => response.json())
  .then(json => console.log(json))

Response

{
  "userId": 1,
  "id": 1,
  "title": "Architecting Resilient Distributed Systems with Node.js and Redis (Production Case Study)",
  "body": "Building fault-tolerant backend services requires careful consideration of network partitions, graceful degradation, and idempotent background processing.\n\nIn this comprehensive overview, we explore how distributed caching patterns and dead-letter queues prevent cascading system failures during peak traffic spikes.\n\nAuthored as part of the technical engineering series by our senior architecture group."
}
fetch('http://localhost:3000/posts')
  .then(response => response.json())
  .then(json => console.log(json))

Response

[
  { "userId": 1, "id": 1, "title": "Architecting Resilient Distributed Systems…", "body": "Building fault-tolerant backend services…" },
  { "userId": 1, "id": 2, "title": "Modern CSS Layouts: Fluid Typography…",      "body": "Container queries have fundamentally shifted…" },
  // … 100 posts
]
fetch('http://localhost:3000/posts', {
  method: 'POST',
  body: JSON.stringify({
    title: 'Building scalable microservices',
    body:  'Mock post payload for local integration testing',
    userId: 1,
  }),
  headers: {
    'Content-type': 'application/json; charset=UTF-8',
  },
})
  .then(response => response.json())
  .then(json => console.log(json))

Response

{
  "title":  "Building scalable microservices",
  "body":   "Mock post payload for local integration testing",
  "userId": 1,
  "id":     101
}

The resource is acknowledged and returned as simulated REST behavior.

fetch('http://localhost:3000/posts/1', {
  method: 'PUT',
  body: JSON.stringify({
    id:     1,
    title:  'Updated title',
    body:   'Updated body content',
    userId: 1,
  }),
  headers: {
    'Content-type': 'application/json; charset=UTF-8',
  },
})
  .then(response => response.json())
  .then(json => console.log(json))

Response

{
  "id":     1,
  "title":  "Updated title",
  "body":   "Updated body content",
  "userId": 1
}

The update request is simulated and verified without modifying static seed sets.

fetch('http://localhost:3000/posts/1', {
  method: 'PATCH',
  body: JSON.stringify({
    title: 'Patched title only',
  }),
  headers: {
    'Content-type': 'application/json; charset=UTF-8',
  },
})
  .then(response => response.json())
  .then(json => console.log(json))

Response

{
  "userId": 1,
  "id":     1,
  "title":  "Patched title only",
  "body":   "Building fault-tolerant backend services requires…"
}

Partial updates merge fields smoothly into the simulated entity.

fetch('http://localhost:3000/posts/1', {
  method: 'DELETE',
})
  .then(response => response.json())
  .then(json => console.log(json))

Response

{}
// Filter posts by userId
fetch('http://localhost:3000/posts?userId=1')
  .then(response => response.json())
  .then(json => console.log(json))

Response

[
  { "userId": 1, "id": 1, "title": "Architecting Resilient Distributed Systems…" },
  // … 10 posts by user 1
]
// Get comments for a post
fetch('http://localhost:3000/posts/1/comments')
  .then(response => response.json())
  .then(json => console.log(json))

// Same as query filter
fetch('http://localhost:3000/comments?postId=1')
  .then(response => response.json())
  .then(json => console.log(json))

Response

[
  {
    "postId": 1,
    "id":     1,
    "name":   "id labore ex et quam laborum",
    "email":  "Eliseo@gardner.biz",
    "body":   "laudantium enim quasi est quidem magnam voluptate ipsam eos…"
  },
  // … 5 comments for post 1
]

Resources

6 core resources, fully accessible via standard HTTP methods.

Resource Count Description
/posts 100 Technical articles with title, body and userId
/comments 500 Discussion comments linked to posts by postId
/albums 100 Photo collections grouped by user
/photos 5000 Image assets with URLs and thumbnails, linked to albums
/todos 200 Task items with boolean completion state
/users 10 Developer profiles with contact and company info
